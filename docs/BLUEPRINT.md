# treasury 蓝图
> 活蓝图：正文永远是当前真相，改了就覆盖。只讲功能不讲实现。
> 重构照本文行为契约重写即可；未列为硬约束的一切都是实现细节，可自由更改。

## 1. 一句话

个人 AI 数据层，只给我自己用。它把多台机器上各 AI 平台（Claude Code、Codex 等）的记忆、skill、插件收进一个不会丢的 git 金库，再按每台机器的订阅装回这台机器启用的平台：一处改动，到处生效。另附一套换电脑时整包迁移 Claude Code / Codex 个人数据的工具。

## 2. 功能与行为 + I/O 契约

**hub（金库的采集、分发、校验）**：

- **收集** `collect`：读 device.toml 里配的源，把本机家当镜像进金库的 `<本机>/` 备份区，并重算金库根的记忆索引。配了但不存在的源，点名报错，一个字节都不写。备份区以外的位置一律不碰。
- **同步** `sync`：拉取 → 校验（scope、裸路径、sensitive）→ 重算索引 → 提交推送。远端连不上会自动重试；内容冲突就停下，要人手工解决。`--refresh` 成功后接着刷新。
- **提升** `promote` / `promote-memory`：把备份区里选定的 skill / 记忆复制进 `shared/`。同名但内容不同就停。
- **注册** `register`：对本机启用的每个平台做四件事——把 `shared/skills` 和随包的 hub-memory 逐个活链进它的 skill 目录，生成它的记忆视图，把视图接进它的入口文件，按 device.toml 收敛插件的安装和启用。先把全部检查做完才动手：链接冲突，或任一启用的平台在本机不可用，就报出全部原因、一个字节都不写、返回非零。
- **刷新** `refresh`：`shared/` 变化后重算视图，并重装已经 bump 版本的插件。遇到不可用的平台，和 `register` 一样零写入。
- **状态** `status [--check]`：金库 git 状态，加上各启用平台的链接、视图、插件健康。某个平台不可用时，报一行 `unavailable`＋原因，其余照常检查。`--check` 遇到任何不健康项返回 1。
- **资产矩阵** `inventory`：输出资产 × 平台的 JSON 矩阵。列只有本机启用的平台，不可用的平台照样出列，单元格标 `unknown`＋原因。
- **开关** `toggle <类型> <名> <平台> on|off`：在一个平台上开关单个插件或 skill，同时改 device.toml 并执行。点名停用或不可用的平台会明确报错。
- **读记忆** `memory-read`：只读本机该平台视图里有的记忆正文；越 scope 或平台已停用，一律拒读。
- **解释 / 巡检** `memory-explain` / `memory-audit`：说清每条记忆进了哪段视图、为什么；列出归档候选。只读。
- **密钥** `secrets exec|run|render|unlock`：exec 给 AI 用，只能跑预先声明的 profile，输出里的密钥被遮罩；另外三条只给人用。

**新设备接入**：把 GitHub 上的 `INSTALL.md` 交给能操作本机的 AI，可按说明拉取工具仓和金库、识别本机路径、沿用参考设备的订阅和插件选择，再接入共享规则、记忆、skills、plugins 并验收。已有规则和本机修改保留；需要本人登录或存在内容冲突时明确报告。README 提供入口，说明中同时区分接收更新与提交推送。

**迁移工具**（`migrate.py` 等）：`export` 把 Claude Code / Codex 的个人数据打包（不含登录凭证），`import` 在新机还原，支持改写用户名和工程路径。

**I/O / 数据契约（换语言必须逐字保留）**：

- 金库目录结构、记忆 frontmatter、scope 语法、device.toml 字段、`shared/plugins/manifest.toml`，都以 `hub/schema_md.py` 生成的 SCHEMA.md 为准。
- **device.toml 顶层 `platforms`**：不写 = 启用 hub 认识的全部平台；`[]` = 全部停用；不是字符串数组，或写了不认识的名字，所有读它的命令都报错。
- **scope 的 `tool:<平台>`**：可写的值是 hub 认识的全部平台，不按本机启用集判。
- **记忆视图**：`~/.hub/views/<平台>/MEMORY.md`，文件头嵌 `shared_hash`，用来判新鲜度。受管块标记是 `<!-- hub:begin -->` 到 `<!-- hub:end -->`，块外内容原样保留。
- **CLI 机器通道**（`--json`）：统一信封 `{ok, data, error, meta}`，退出码 0 / 1 / 2，错误码表见 `hub --ai-help`。`status --json` 的平台附加行键名（`opencode_links`、`dsh_loader`）、`register --json` 的计数键名、`inventory` 顶层的 `harnesses`，都属于契约。

## 3. 边界 / 明确不做

- 收集和同步永远不把备份写回工具目录。只有用户显式调用的注册类命令才会写工具目录。
- 插件的装卸只走各平台的官方 CLI，不直接改平台的缓存和配置文件。
- 不删用户的东西：链接冲突就停；停用平台留下的旧视图、旧链接不自动清。
- 平台停用不等于插件不要了：已经装着的插件原样留着，不卸载。
- 平台专属的 hook（如 PreCompact）不跨平台分发。

## 4. 硬约束 + 重构自由声明

- 只用 Python 标准库，Windows 上用 `py -3` 调用。
- 密钥路径永远不读，sensitive 记忆永远不入库。
- `--dry-run` 一个字节都不落盘。
- 写命令先做完全部只读检查再动笔，检查里出现确定性错误就零写入。
- 平台是一条变化轴：加或去掉一个平台，只动它自己的适配器和注册表。一个平台出错只影响它自己——聚合检查照常报其余平台，写命令则整体零写入。
- **以上未列出的一切均为实现细节，重构可随意更改。**

## 5. 功能痛点 / 易错点

- 配错的源路径不等于用户删光了记忆。镜像语义下，把前者当后者处理会清空金库，所以必须先验源、再写。
- 把带 `.git` 的目录直接纳入父仓，记下的是 gitlink 空壳：本机看着正常，别的机器 clone 下来是空的。
- 停用一个平台时，最容易把"平台不要了"错当成"插件不要了"，生成卸载动作。
- opencode.json 里有明文密钥：只在 device.toml 显式配了路径时才碰它，格式不严格就拒改。
- 平台依赖缺失和用户配置冲突是两回事。前者叫不可用，要隔离；后者叫冲突，要停下等人处理。
